# F50 安装与在线更新

选择 [GitHub Releases](https://github.com/helloworlde/cowplay/releases) 中适用于设备的渠道和版本。开发包标记为 Pre-release，正式版须另行验收确认。安装覆盖程序与 LuCI 页面，保留私有状态，过程中连接会中断。

## 命令行首次安装

按 [README 的 OpenWrt 命令](../README.md#f50--mu300-openwrt) 导入发布公钥，通过签名 `packages.adb` 使用标准 `apk add --repository` 安装两包。该软件源须先公开发布；旧版附件尚无索引。此入口仅用于首次安装，后续使用 LuCI 更新流程检查兼容性并备份状态。安装后执行 `cowplay update-bootstrap` 初始化更新信任；为全新状态目录执行一次 `cowplay init-access /etc/cowplay/state`，它拒绝覆盖已有访问状态。

配置示例安装在 `/usr/share/cowplay/config.example.json`。准备本地合法身份、热点与可信 HTTPS 文件，写入 `/etc/cowplay/state/config.json` 后再启动服务。配置和私钥权限为 `0600`，私有状态目录为 `0700`。

MU300 OpenWrt 必须保留厂商 5.4 蓝牙驱动、`/opt/mu300/bin/mu300-bt-init` 和 `/lib/firmware/bt_configure_{pskey,rf}.ini`。CowPlay 启动时完成初始化并运行包内 `/usr/lib/cowplay/bluez`，无需另外安装 BlueZ 包；不替换系统驱动或安装官方 6.12 内核模块。若已有程序占用控制器，先确认并协调该程序，CowPlay 不会强行接管。

## 首次安装：只有 LuCI 软件包页时

1. 等仓库公开，并确保 F50 可访问 GitHub。打开 LuCI“系统 → 软件包”，更新列表，从设备已有官方源安装 `luci-app-commands` 和 `curl`。不要安装内核模块或更换软件源。
2. 刷新 LuCI，打开“系统 → 自定义命令 → 配置”（英文为 Custom Commands → Configure）。添加一个命令，描述填写“安装 CowPlay”。**不要勾选“公开访问”或“自定义参数”。** 此操作继续使用已有 LuCI 登录和 HTTPS。
3. 从所选 Release 正文“LuCI 首次安装命令”复制完整命令到“命令”，保存并应用。命令固定版本、渠道、脚本 SHA-256 和发布公钥指纹。
4. 在“自定义命令 → 概览”点击“安装 CowPlay”。页面显示 Started 表示后台任务已启动，**不代表安装完成**。不要重复点击，也不要断电。
5. 可添加第二个命令 `cat /tmp/cowplay-install.log`，名称为“安装进度”，同样保持非公开。运行它查看结果。出现 `CowPlay is ready` 后刷新 LuCI，即可使用新页面。

官方 LuCI 的软件包 URL 输入框不能可靠处理 APK 下载，直接上传陌生公钥签名的包也会被拒绝。因此首次使用上述官方自定义命令入口；不需要关闭 APK 签名、HTTPS 或登录校验。[LuCI 官方说明](https://github.com/openwrt/luci/issues/8410)、[官方自定义命令页面](https://github.com/openwrt/luci/blob/openwrt-25.12/applications/luci-app-commands/htdocs/luci-static/resources/view/commands.js)。

可信发布公钥 SHA-256：

```text
5f926239adc2029a33ed58c6e7e2107dcc424fb7e8133cdbdcb777e5f1a8b40f
```

脚本先验证公钥、签名清单和辅助程序，再下载并验证双 APK；校验和依赖检查通过后才停止 CowPlay。首次引导不替换不同的既有发布来源或公钥。管理员执行固定安装命令即授权该次安装；后续网页更新仍需确认。

## 后续检查与更新

LuCI“服务 → CowPlay → 系统 → GitHub 安装与升级”：

1. 选择“正式版”或“开发版（Pre-release）”渠道；留空“版本标签”检查该渠道最新版本，也可指定同渠道标签。
2. 有新版本时显示版本与架构；点击“安装所选版本”，确认后执行。
3. 确认候选渠道和版本，安装完成后刷新页面。切换渠道必须重新检查；检查或取消确认不会安装，切换渠道不能绕过降级与兼容性限制。

下载或校验失败不会停止服务。安装失败会保留设备内备份和任务状态；先核对日志、软件包与服务，不盲目降级或恢复旧状态。首次安装失败且新 LuCI 页面尚未安装时，仍可从“自定义命令”查看安装进度。仓库为私有时匿名检查会失败，不要在设备中保存 GitHub 私人令牌来绕过。

## Tesla 管理入口

Tesla 位于 CarPlay“设置 → Tesla 车辆”（`/car#settings/tesla`），与画面、声音与麦克风共用侧栏和设置面板。车辆管理、配对、空调控制在同一面板内切换；使用与 CowPlay 管理相同的独立令牌，在面板内解锁。LuCI Tesla 入口也指向这里，LuCI 表单仍可使用。

OpenWrt 现有配置默认未启用独立管理认证。管理员需在已有服务 JSON 配置中设置现有的 `management_token_file` 字段，指向私有状态目录内的令牌文件。文件内容为 32 个随机字节的 64 位十六进制文本，须由运行服务的用户持有、权限 0600，父目录限制为该用户可访问。不要覆盖已有令牌；生成与文件检查见 [Linux 管理配置](LINUX.md#系统蓝牙与私有配置)。配置变更需在获得设备操作授权后重启服务，随后可在 Tesla 面板内解锁。六位投屏访问码、LuCI cookie 均不能登录此页；未配置时继续使用 `/cgi-bin/luci/admin/services/cowplay/tesla`。

流程沿用手机配对管理的显式操作与取消：添加 Tesla → 输入 VIN 并确认保存（新车辆默认勾选启用）→ 开始配对 → 在车内确认 → 返回车辆管理连接读取。未启用时保存不会开始蓝牙操作。失败、超时和取消保留配置与身份，可明确重试；离开 Tesla 子页会停止页面轮询，车辆连接由“断开”操作结束。只读监控配对与 Driver 控制授权分别管理；原生 CarPlay UI 可离线浏览，实际控制仍需当前会话与授权。

## 清理车机页面

连接页或“设置 → 关于”点击“清理页面缓存并重新打开”；也可在相同可信 HTTPS 地址直接打开 `/car/reset`。此入口清理该站点的浏览器缓存后打开最新车机页面，保留浏览器访问身份、画面偏好、iPhone 与 Tesla 配对。它不重置服务配置或访问码；网页接入不使用构建号／协议号拦截。

## 设备访问码（可选）

首次打开全新 CowPlay，在车机或手机页面选择：设置两次相同的六位数字访问码，或明确选择“不设置访问码”。无需先登录 LuCI。选择保存在接收端，重启和覆盖安装不会改变；只有受保护的管理操作才能修改。

启用访问码后，新浏览器必须输入正确码，错误拒绝访问。验证一次后分别记住各浏览器；清除浏览器数据或撤销授权后需重新验证。二维码只打开页面。未启用访问码时，能打开此地址的设备可直接进入投屏和手机管理；仍保存独立浏览器身份和屏幕设置。

登录 LuCI → 服务 → CowPlay → 设备与访问，可显示、设置、重置或停用访问码。Linux 的独立管理页提供同等能力。由免码改为设码时，免码进入的浏览器需验证一次；此前已验证的浏览器保留授权。普通改码/重置后旧码不能再授权新浏览器，已有验证身份、偏好和 iPhone 配对保留。

已有设备保留原访问选择和浏览器授权；不会因设备列表为空或读取失败重新开放首次选择。此码与蓝牙配对码、Tesla 车辆钥匙授权及管理登录独立。
