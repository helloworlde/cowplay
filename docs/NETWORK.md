# 端口与访问配置

## 配置入口与职责

入口：**LuCI → 服务 → CowPlay → 网络与证书**。

| 区域 | 内容 |
| --- | --- |
| 访问地址与端口 | 访问域名、HTTPS 端口、实际占用者；支持 1–65535，包括 443，默认 18443 |
| HTTPS 证书 | 证书链和私钥，均支持直接粘贴或文件导入，校验后立即替换；无需填写 DNS 参数 |
| 证书申请与续期 | 独立、默认折叠的可选入口；DNS-01 仅用于向 CA 证明域名控制权，以申请或续期证书 |
| OpenWrt 无线设置 | 热点由系统配置；CowPlay 使用既有 `wifi_iface` 数据进行连接交接 |

DDNS 更新地址、DNS-01 验证域名和安装 HTTPS 证书是不同操作。手动导入证书无需填写 DNS 提供商或 API 凭据。证书、访问令牌和 Origin 校验保持启用。

## 已占用端口的保存与覆盖

占用检查显示服务名、PID 和监听地址。占用不阻止保存配置，保存本身不停止服务；应用变更前需要重新确认影响。

选择“保存并应用”时重新核对目标端口和占用者。对可识别、可恢复的 procd 服务，弹窗列出实际影响，点击“覆盖并应用”后执行：

1. 记录配置、进程身份和原运行端口，取得独占任务锁，应用 UCI 配置。
2. 若占用者为 uhttpd，先新增空闲的 HTTPS 管理端口，保留旧监听；浏览器以原协议确认管理入口可用后，才释放原端口。保留非冲突监听、HTTP、证书和其他 uhttpd 配置。
3. 停止其他已确认的占用服务，重新检查端口，再启动或重启 CowPlay。任务由独立进程执行，不依赖被重启的 CowPlay 或原 RPC 连接存活。
4. 同时验证 CowPlay 的实际 PID/监听归属、可信 TLS 和精确健康响应，才报告接管成功。普通 HTTPS 200、进程存活或 init 返回 0 均不足以通过。

管理入口未确认、占用者变化、启动或 HTTPS 验证失败，会恢复配置及此前停止的服务；恢复不完整时保留备用管理入口并显示“恢复原配置”。恢复按组件继续执行，一项配置冲突或记录写入失败不会跳过其他服务恢复；不覆盖期间由外部修改的配置。

任务记录和配置备份只存于 root 私有的 `/var/run/cowplay-network`，目录 0700、文件 0600，公开状态不含配置备份。确认标记与任务日志分离，避免迟到的浏览器确认覆盖恢复进度。准备后 UCI 已应用但尚未启动接管的中间状态也可撤销。

自动接管仅适用于已核实归属的受支持服务；未知进程、基础系统服务或无法确定的跨地址族冲突仍可保存，但不会盲目结束进程。其他占用服务只停止、不改变其自启状态，重启设备后可能再次冲突；uhttpd 的备用监听配置会持久保存。IPv6 通配监听不被猜测为必然占用 IPv4。
