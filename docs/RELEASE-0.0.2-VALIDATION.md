# 0.0.2 可选访问码验证

首次使用可以设置六码或明确选择不设置，不依赖 LuCI。访问选择持久保存。缺失、损坏或保存失败不会自动进入免码模式。免码仍使用独立浏览器身份、可信 HTTPS 和 Origin 校验。

免码进入的浏览器在开启访问码后必须验证；正在投屏的连接会撤权。正确码复用原身份和偏好；此前可信身份及普通改码后的已验证浏览器保留。LuCI、Linux 管理端可设置、重置或停用访问码，普通网页授权不授予管理权限。

## 验证

- 完整 Rust workspace：432 通过，1 项需要外部 ACME 条件的测试按既有规则忽略。新增真实回环 WebSocket 撤权／重新验证，以及三态持久化、首次选择竞争、保存失败和管理权限回归。
- 真实 Chrome DOM／合成接收端：首次两种选择、取消、不同确认码、错误码拒绝、不同浏览器、Cookie 未保存、另一浏览器先完成选择、提交期间互斥、800×480 车机布局通过。
- LuCI 操作回归通过；首次调用缺少 LUCI_RUNTIME_DIR，补齐已安装运行资源路径后运行。Linux 管理回归通过；新增取消用例首次在 close 事件结束前点击仍禁用按钮，已改为等待实际关闭与按钮恢复，不修改超时或业务断言。
- 初始配对界面回归发现旧断言仍检查“令牌不对”，而合成 API 已使用“访问码不对”；统一服务文案与精确断言，并等待错误处理结束、输入恢复可用再重试，完整配对入口最终通过；投屏恢复回归也通过。
- 独立评审发现并修复首次选择冲突后的页面恢复、免码内部标记显示、设码提交时仍可发起免码请求。访问码读取与身份校验同锁，避免切换模式时泄出新码。

## 发布与边界

0.0.1 已发布，附件保持不变；本次使用 v0.0.2 / 0.0.2-r0。清单支持完整 r34 双包直接覆盖及从 0.0.1 更新，其他降级／混合包版本继续拒绝。新免码状态不能直接由 0.0.1 读取，不承诺仅覆盖旧二进制回退。

发布必须等待两个架构 Actions、隔离安装和生产附件重新下载核验全部通过。真实 iPhone CarPlay、媒体绘制、音频、车辆和长期稳定性另行验收；网页与模拟回归不替代现场结果。原生 CarPlay 图标慢／缺失仍缺现场资源证据。
